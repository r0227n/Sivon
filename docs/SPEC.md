# Sivon 仕様書（MVP）

## 1. 目的

Sivon は、macOS 向けのシンプルな ToDo アプリである。MVP では「今日やること」と「期限切れになったこと」に集中し、終わらなかったタスクを少ない操作で未来へ送れる体験を提供する。

成功条件は以下とする。

- ユーザーが起動直後に今日やるべきタスクだけを確認できる。
- 期限切れタスクが明確に分離され、再スケジューリングできる。
- タスクの作成、編集、完了、削除、期限日変更がローカルで永続化される。
- MVP 外の分類機能を持ち込まず、日付と完了状態だけでタスク状態を管理できる。

## 2. 技術構成

| 項目 | 内容 |
| --- | --- |
| 開発言語 | Swift |
| UI フレームワーク | SwiftUI |
| アーキテクチャ | TCA（The Composable Architecture） |
| 永続化 | SwiftData |
| 対応プラットフォーム | macOS 14+ |
| 将来展開 | iOS、ウィジェット、通知、クラウド同期 |

## 3. MVP スコープ

### 3.1 MVP で提供する機能

- タスク作成
- タスク編集（タイトル、メモ、期限日）
- タスク削除
- 完了 / 未完了の切り替え
- 期限日の設定、変更、削除
- 今日、すべて、期限切れ、完了の各ビュー表示
- 期限切れタスクの再スケジューリング
- ローカル永続化

### 3.2 MVP で提供しない機能

- タグ
- カテゴリ
- フォルダ階層
- 複数リスト
- サブタスク
- 繰り返しタスク
- 通知
- クラウド同期
- iOS 対応
- 複数デバイス間の競合解決

## 4. データモデル

### 4.1 Task

`Task` はユーザーが管理する作業単位である。MVP ではタスクの分類を増やさず、完了状態と期限日で表示場所を決める。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | `UUID` | 必須 | タスク識別子。作成時に生成する。 |
| `title` | `String` | 必須 | タスク名。空文字または空白のみは保存しない。 |
| `notes` | `String?` | 任意 | 補足メモ。未入力の場合は `nil` または空文字として扱う。 |
| `isCompleted` | `Bool` | 必須 | 完了状態。初期値は `false`。 |
| `dueDate` | `Date?` | 任意 | 実行予定日。未設定の場合は未計画タスクとして扱う。 |
| `createdAt` | `Date` | 必須 | 作成日時。 |
| `updatedAt` | `Date` | 必須 | 最終更新日時。作成時は `createdAt` と同じ値にする。 |

### 4.2 日付の扱い

- 「今日」はユーザーの現在カレンダーと現在タイムゾーンにおける日付とする。
- ビュー判定では時刻を無視し、カレンダー日付だけを比較する。
- `dueDate == nil` のタスクは、今日ビューにも期限切れビューにも表示しない。
- `updatedAt` はタイトル、メモ、完了状態、期限日のいずれかが変わったときに更新する。

## 5. ビュー種別

MVP のビュー種別は以下の 4 種類に固定する。

| 値 | 表示名 | 定義 |
| --- | --- | --- |
| `today` | 今日 | `dueDate` が今日、かつ `isCompleted == false` |
| `all` | すべて | 全タスク |
| `overdue` | 期限切れ | `dueDate` が今日より前、かつ `isCompleted == false` |
| `completed` | 完了 | `isCompleted == true` |

表示順の初期方針は以下とする。

- 今日ビュー: 期限日昇順、作成日時昇順。
- 期限切れビュー: 期限日昇順、作成日時昇順。
- すべてビュー: 未完了を先に表示し、期限日昇順、作成日時昇順。
- 完了ビュー: 更新日時降順。

## 6. UI 仕様

### 6.1 全体レイアウト

macOS 標準の 3 カラム構成とする。

1. サイドバー: ビュー選択。
2. タスク一覧: 選択中ビューに該当するタスクを表示。
3. タスク詳細: 選択中タスクの詳細編集。

アプリ起動時の初期選択は今日ビューとする。

### 6.2 サイドバー

サイドバーには以下を表示する。

- 今日
- すべて
- 期限切れ
- 完了

各項目には件数を表示してよい。件数を表示する場合、今日と期限切れは未完了のみを数える。

### 6.3 タスク一覧

タスク一覧は選択中ビューに応じてフィルタ済みのタスクを表示する。

各行に表示する情報は以下とする。

- 完了切り替えチェックボックス
- タイトル
- 期限日
- 期限切れ状態の視覚的な強調

一覧上部には新規タスク入力を置く。タイトルを入力して Enter を押すとタスクを作成する。作成時の `dueDate` は、今日ビューでは今日、それ以外のビューでは未設定を初期値とする。

### 6.4 タスク詳細

タスク詳細では以下を編集できる。

- タイトル
- メモ
- 期限日
- 完了状態

選択中タスクがない場合は空状態を表示する。空状態では、タスクを選択するか新規作成できることが分かる最小限の表示にする。

### 6.5 削除

削除操作はタスク詳細または一覧のコンテキストメニューから実行できる。

- 削除前に確認を表示する。
- 選択中タスクを削除した場合、詳細ペインは未選択状態になる。
- 削除後は即座に一覧から取り除き、永続化する。

### 6.6 期限日変更と再スケジューリング

期限日変更はコア操作として扱う。今日ビューと期限切れビューでは、一覧行またはコンテキストメニューから素早く変更できる。

選択肢は以下とする。

- 今日
- 明日
- 来週
- 日付選択
- 日付なし

期限切れタスクに新しい期限日を設定した場合、そのタスクは現在のビュー条件に合わなくなれば一覧から移動する。日付なしにした場合、今日ビューと期限切れビューには表示されない。

## 7. タスク操作

### 7.1 作成

- タイトルは必須。
- タイトルの前後空白は保存前に取り除く。
- 空文字または空白のみのタイトルでは作成しない。
- 作成時に `id`、`createdAt`、`updatedAt` を設定する。

### 7.2 編集

- タイトル、メモ、期限日を編集できる。
- タイトルを空にして保存しようとした場合は保存せず、ユーザーにエラーを示す。
- 編集が成功した場合は `updatedAt` を更新する。

### 7.3 完了切り替え

- チェック操作で即時に `isCompleted` を切り替える。
- 完了にしたタスクは今日ビューと期限切れビューから除外し、完了ビューに表示する。
- 未完了に戻した場合は、期限日に応じて今日、期限切れ、またはすべてビューに表示される。

### 7.4 削除

- 削除確認後にタスクを削除する。
- 削除したタスクは復元しない。
- MVP ではゴミ箱やアーカイブは提供しない。

## 8. 状態管理（TCA）

### 8.1 Feature 構成

TCA の責務分割は以下を基本とする。

- `AppFeature`: 全体状態、起動時ロード、永続化依存、サイドバー選択、タスク配列を管理する。
- `SidebarFeature`: ビュー選択と件数表示に必要な状態を扱う。
- `TaskListFeature`: 選択中ビューのタスク表示、新規作成、完了切り替え、再スケジューリング操作を扱う。
- `TaskDetailFeature`: 選択中タスクの詳細編集、削除、保存エラー表示を扱う。

### 8.2 State

- 単一のタスク配列をソースオブトゥルースとする。
- 選択中ビューは `today`、`all`、`overdue`、`completed` のいずれかとして保持する。
- 選択中タスクは `Task.ID?` として保持する。
- 各ビューのタスク一覧は、タスク配列と選択中ビューから導出する。

### 8.3 Action

主要アクションは以下とする。

- タスク作成
- タイトル編集
- メモ編集
- 完了切り替え
- 期限日変更
- 期限日削除
- タスク削除
- サイドバー選択
- タスクリスト選択
- 起動時ロード
- 永続化成功
- 永続化失敗

### 8.4 Dependency

永続化処理は依存関係として注入する。Reducer は SwiftData の具体 API を直接呼び出さない。

永続化依存は少なくとも以下の操作を提供する。

- 全タスク読み込み
- タスク作成
- タスク更新
- タスク削除

## 9. 永続化（SwiftData）

### 9.1 基本方針

- タスクは SwiftData でローカル永続化する。
- アプリ起動時に全タスクを読み込み、TCA の状態へ反映する。
- 作成、編集、削除、完了切り替え、期限日変更のたびに保存する。
- 保存後の状態が SwiftData と TCA の状態で一致するようにする。

### 9.2 エラー処理

永続化に失敗した場合は以下のいずれかで整合性を保つ。

- 失敗した操作をロールバックする。
- SwiftData から再読み込みして状態を復旧する。

ユーザーには保存に失敗したことを分かる形で表示する。MVP では詳細な復旧 UI は不要だが、失敗を黙殺してはならない。

## 10. UX 方針

- 最小操作でタスクを追加できる。
- クリックまたはキーボード操作で完了にできる。
- 期限切れタスクは視覚的に強調する。
- インボックス、タグ、カテゴリを導入せず、日付の有無と完了状態だけで判断できる。
- コア体験は「終わらなかったタスクを自然に未来へ送る」こととする。

## 11. 状態遷移

```text
タスク作成
   ↓
未計画（dueDate なし）
   ↓
日付設定
   ↓
今日タスク / 未来タスク
   ↓
未完了のまま dueDate が過去になる
   ↓
期限切れ
   ↓
日付再設定
   ↓
今日 / 未来 / 未計画
```

完了したタスクは期限日に関係なく完了ビューへ移動する。未完了へ戻した場合は、その時点の期限日に応じて各ビューに再分類される。

- 静的解析

## 13. テスト方針

### 13.1 Unit Test

- 各ビューのフィルタ条件が正しい。
- 完了タスクが今日ビューと期限切れビューから除外される。
- 期限切れタスクを今日、未来、日付なしへ変更できる。
- 作成、編集、削除、完了切り替えで `updatedAt` が期待通り更新される。

### 13.2 Reducer Test

- タスク作成後に一覧へ反映される。
- サイドバー選択で表示対象が切り替わる。
- 選択中タスクを削除した場合、詳細ペインが未選択になる。
- 永続化成功時に状態が維持される。
- 永続化失敗時にエラー表示と状態復旧が行われる。

### 13.3 手動受け入れ確認

- アプリを再起動してもタスクが保持される。
- 今日ビューで今日の未完了タスクだけに集中できる。
- 期限切れビューで期限切れの未完了タスクだけを確認できる。
- 期限切れタスクを少ない操作で今日、明日、来週、任意日、日付なしへ移動できる。
- MVP 外機能が UI に表示されない。

## 14. 実装境界

### 14.1 Always

- この仕様書を実装判断の基準にする。
- Reducer から SwiftData の具体 API を直接呼ばず、依存関係経由にする。
- 日付比較では時刻を無視し、カレンダー日付で判定する。
- 保存失敗をユーザーに表示する。
- 仕様変更が必要になった場合は、実装前に本仕様書を更新する。

### 14.2 Ask First

- MVP 外機能を追加する。
- データモデルの必須フィールドを変更する。
- macOS 14+ 以外を正式サポート対象にする。
- SwiftData 以外の永続化方式へ変更する。
- TCA 以外のアーキテクチャへ変更する。

### 14.3 Never

- タイトルが空のタスクを保存しない。
- 保存失敗を黙殺しない。
- 完了済みタスクを今日ビューまたは期限切れビューに表示しない。
- タグ、カテゴリ、複数リストを MVP に混ぜ込まない。
- ユーザーデータをクラウドへ送信しない。
